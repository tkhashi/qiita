# はじめに

Muse にブラウザ作業を頼むと、途中の画面をスクリーンショットで見せてくれます。
ところが、その画像をファイルとして手元に残そうとすると詰まります。資料に貼りたい、他の人に渡したい、作業の記録として残したい——そう思っても、取り出す経路が見当たらないのです。

- スクリーンショットは撮れるし、エージェントはその場で目視確認もできる
- しかし **画像ファイルとして取り出す経路が見当たらない**
  - ワークスペースやダウンロードフォルダにファイルとして残らない
  - アップロードのファイル選択にも渡せない

本記事は、試行錯誤の末に見つけた「撮影画像は実は VM 上にファイルとして保存されていた」という回収方法の記録です。
なお、これは 2026年11月時点の Muse の環境で確認した挙動で、公式に案内された保存機能ではありません。将来的に変わる可能性があります。

# ダメだった経路

組み込みブラウザの内部で完結させる方法は、一通り試してすべてダメでした（2026-11-15 に example.com で実機テスト）。

| 経路 | 結果 |
|---|---|
| スクショをファイル／保護された成果物としてチャットやライブラリに渡す | 経路自体がない。スクショはセッション内の表示専用で、ファイル ID を持たない |
| クリップボード（Ctrl+C / Ctrl+V） | ショートカット自体が「Clipboard shortcuts are unavailable」として明示的に拒否される |
| ブラウザ内から Web サイトへアップロード | タスクに事前に「ファイルとして渡されたもの」しか選べない。セッション内で生成したファイルを指定しても granted ではないとして拒否される |
| Ctrl+P（印刷） | 印刷ダイアログもファイルも生成されなかった |

ブラウザを操作する担当（worker）のツールからは、スクショの保存先が一切見えません。
担当に何度聞いても「ファイルは存在しない」という答えになる、というのがこの問題の厄介なところでした。

# 見つけた保存先

メインエージェント側の VM のファイルシステムを直接調べたところ、隠しフォルダに撮影画像が残っていました。

```
~/workspace/.hatch-browser/snapshots/browser-task:<タスクID>/<UTCタイムスタンプ>/look.0.jpg
~/workspace/.hatch-browser/snapshots/browser-task:<タスクID>/<UTCタイムスタンプ>/manifest.json
```

- `look.0.jpg`：その時点のビューポートのピクセル画像（JPEG 形式）
- `manifest.json`：撮影情報のメタデータ

```json
{
  "ts": "20260101T120000.000000000Z",
  "url": "https://example.com/dashboard",
  "title": "ダッシュボード - サンプルサービス",
  "viewport": {"w": 1200, "h": 900, "scroll_y": 0, "scroll_max": 0},
  "files": [{"name": "look.0.jpg", "sha256": "...", "bytes": 81234}]
}
```

URL・タイトル・ビューポートサイズ・ハッシュまで記録されているので、目的の1枚を特定できます。

# 回収手順

1. ブラウザタスクを実行し、タスク ID（`browser-task:xxxx`）を控える
   - 過去分は `~/workspace/.hatch-browser/snapshots/` のフォルダ名からも辿れる
2. `manifest.json` の URL／タイトルで目的のページを探す

```bash
cd ~/workspace/.hatch-browser/snapshots/browser-task:<タスクID>/
grep -l "dashboard" */manifest.json   # URL の一部で検索
grep -l "ダッシュボード" */manifest.json            # タイトルでも検索可
```

3. 候補の manifest で URL／タイトルと `ts`（撮影時刻）を確認し、目的の1枚を特定する
   - 同じページが何度も撮られているのが普通なので、時刻で選ぶ
4. 通常のワークスペースへ、意味のある名前でコピーする（原本は消さない）

```bash
cp <候補フォルダ>/look.0.jpg ~/workspace/<用途フォルダ>/<画面名>.jpg
```

これで通常の画像ファイルとして、添付やアップロードに使えます。

# 注意点

- **公式保証された保存機能ではなく、内部保存です。** 保持期間やパスの形式が変わる保証はありません
- 形式は JPEG のみです（PNG が必要な場合はコピー後に変換）

# 代替経路

## ページ PDF（劣位のフォールバック）

ブラウザの「ページを PDF として保存」は、実ファイルが VM に落ちる数少ない経路でした。

```
~/workspace/.hatch-browser/outputs/<タスクID>/browser-page-*.pdf
```

ただしこれは印刷レイアウトでの描画であり、画面のピクセルそのままではありません。
SPA やモーダルダイアログではレイアウトが崩れる実績があり（PDF 自体は取れても「スクショ」としては不合格でした）、
スナップショット回収が使える場面ではそちらを優先します。

## VM 上の Chromium を別途操作する

組み込みブラウザではなく、VM 上に用意した Chromium（Playwright 等）をエージェント自身が操作すれば、撮影画像は最初から通常ファイルとして保存できます。実際、ログイン不要のページや手元のアプリでは、この方式で問題なく撮影できました。

ただし、ログインが必要な外部サイトでは「撮影」以前の段階で詰まりました。

- VM からの通信は認証付きプロキシ経由で、Chromium からその認証を送れず、中継を別途立てる必要があった
- プロキシが証明書を差し替える方式で Chromium に弾かれた（検証を緩めると通過はする）
- 組み込みブラウザのログイン済みセッションは持ち込めないため新規ログインが必要になり、CAPTCHA や 2FA の壁に当たった
- 最終的に、対象サイト側に対策されているらしい挙動が見られ、この経路は断念した

「ファイルとして保存できるか」自体は Yes でも、サイトへの到達とログインが別問題として立ちはだかる、という結果でした。

# まとめ

- Muse 組み込みブラウザのスクショは、担当ツールの視点では「ファイル化できない」が、VM の隠しフォルダ `~/workspace/.hatch-browser/snapshots/` に JPEG として保存されている
- `manifest.json` の URL／タイトル／撮影時刻で選別してコピーすれば、通常の画像ファイルとして回収できる

エージェントに「できない」と言われたことでも、実行環境のファイルシステムまで降りて調べると活路がある、という一例でした。
