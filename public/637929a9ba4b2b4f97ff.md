# Codex CLIでローカルMCPサーバーを叩いてみる。
- 国土交通データプラットフォームというデータセットと、そのAPIアクセス用のMCPサーバーが公開されていたのでこちらを叩いてみる。
    - https://www.mlit-data.jp/#/DataCatalogList
- このデータセットはCSVや3次元点群データなどのファイルデータがあるので、エージェント自身にデータのDLから解析まで行ってもらうためにCodex CLIのようなCLIツールをMCPクライアントとした。
    - Gemini CLIでもClaude Codeでもよい。

# APIキーの取得と環境構築
- pythonをインストールしておく
- STEP3の手順でAPIキーを取得しておく
    - 今回はClaude Desktopを使わないのでその他は無視
    - https://www.mlit-data.jp/cms//api/v1/pages/_page/apps_mcp/MCP_InstallationGuide.pdf
    - 以降のコードでは `/Users/username/Documents/github` ディレクトリにcloneした前提で説明

# MCPサーバーの設定

- `~/.codex/config.toml`を編集
    - 各種パスを取得しておく
    - APIキー、パスは各々の環境に合わせたものを記載する。


```sh
$ which python3
/Users/username/Documents/github/mlit-dpf-mcp/.venv/bin/python3

$ pwd
/Users/username/Documents/github/mlit-dpf-mcp

```


```toml
# ↓この辺は好み
hide_agent_reasoning = false # 思考過程の非表示
network_access = true
model = "gpt-5-codex"
model_reasoning_effort = "high"
# ↑

[mcp_servers.mlit-dpf-mcp]
# which python3で得られたパス
command = "/Users/username/Documents/github/mlit-dpf-mcp/.venv/bin/python3"
args = [ "-m", "src.server" ]

# 環境変数
# https://www.mlit-data.jp/cms//api/v1/pages/_page/apps_mcp/MCP_InstallationGuide.pdf
[mcp_servers.mlit-dpf-mcp.env]
# 国土交通データプラットフォームで取得したAPIキー
MLIT_API_KEY = "YOUR-API-KEY"
MLIT_BASE_URL = "https://www.mlit-data.jp/api/v1/"
PYTHONUNBUFFERED = "1"
LOG_LEVEL = "WARNING"
# pwdで得られたMCPサーバーの実行ディレクトリ
PYTHONPATH = "/Users/username/Documents/github/mlit-dpf-mcp"

```

# 実行

## MCPサーバーの実行

- 仮想環境立てた状態で下記を実行

```sh
$ python /Users/username/Documents/github/mlit-dpf-mcp/src/server.py
```

特になんのレスポンスもなく、Enter押すと下記のようなエラーを吐く。
これはMCPサーバーに対してパラメータなしでリクエストしたことによるもの。


# 東京圏 QOL 調査レポート（MLIT DPF MMAベース）

## 1. 調査サマリー
- MLITデータプラットフォーム「都市QOL都市圏（dataset: `qol_mma`, 年次: 2020, 最終更新: 2025-08-13）」のメッシュデータから東京都の全53市区を抽出。
- QOLスコアは都市圏平均を0とした相対指標。東京都平均は139,727。文京区は平均743,605でトップ、練馬区まで城西エリアが上位を占めた。
- 文京区は全42メッシュの8割超が+40万以上を維持し、最高値は小石川〜春日エリア（KeyCode 533945682, スコア1,000,886）、最低でも湯島東部（533945694, 382,485）。
- 利便指標（病院・鉄道・買物・求人）は都平均を大幅に上回る一方、「住宅の静けさ」「身近な緑」はマイナス圏で、静穏性を重視する場合は周辺区との比較が必要。

## 2. データソースと処理
- **一次データ**: `data/QOL_TokyoMA.csv`（MLIT DPFより取得）。指標はQOLと生活利便・リスク系16項目、KeyCodeはJIS 1kmメッシュ（4分割）。
- **前処理**: pandasで東京都レコードを抽出し、市区別にQOLを平均化 (`outputs/tokyo_qol_city_summary.csv`)。文京区のKeyCodeは標準メッシュに変換し座標化。
- **可視化**: Matplotlib + Spectral_rカラーマップで文京区42メッシュを散布図ヒートマップ化 (`outputs/bunkyo_qol_heatmap.png`)。
- **指標比較**: 全17指標について文京区平均と都平均を比較し、指標ごとの市区内順位や偏差を `outputs/bunkyo_indicator_stats.csv` に集計。

# 東京でQOLの最も高い地域を調べて
作成日: 2025-11-14

## 1. 調査指標とデータソース
- **住みここちスコア（丁目別）**: 2024年6月13日発表の「いい部屋ネット 街の住みここちランキング＠東京都版」。東京都では13,521人が回答し、調査期間は2023年9月1日～2024年3月8日のインターネット調査として実施された。citeturn0search5
- **幸福度スコア（丁目別）**: 同シリーズで公開された「街の幸福度ランキング」では、日常生活で感じる充足感や地域愛着を指標化しており、都心部の超都心エリアが上位に入っている。citeturn0search4

## 2. 指標別トップエリア（2024年データ）
**街の住みここち（丁目）ランキング**
1. 世田谷区松原（5年連続1位）
2. 渋谷区西原
3. 目黒区自由が丘citeturn0search0

**街の幸福度（丁目）ランキング**
1. 港区愛宕（初の1位）
2. 港区芝公園
3. 千代田区永田町citeturn0search0

## 3. 総合候補の整理
### 3.1 世田谷区松原（推奨エリア）
- 住みここち指標で唯一5年連続の首位となり、調査母数も東京都内13,521サンプルあるため、汎用性の高い満足データとして解釈できる。citeturn0search5
- 最寄りは京王線と京王井の頭線が交わる明大前駅で、新宿・渋谷の主要ターミナルへ10分前後で到達でき、通勤・通学の移動時間を短縮しやすい。citeturn0search7
- 高架下や駅周辺にスーパーや個店が密集し、生活必需品が徒歩圏で完結するローカルな商圏が形成されている。citeturn0search7
- 低層住宅と緑地が中心の静かな街並みが維持されており、騒音や過密感を抑えながら世田谷らしい落ち着きを享受できる。citeturn0search7
- 留意点：主な鉄道は京王系2路線に限られるため、JRや東京メトロ直通を日常的に使う場合は明大前での乗り換えが前提になる。これは最寄り駅の紹介が京王線のみであることに由来する調査記事からの推測で、実地確認が必要。citeturn0search7

### 3.2 港区愛宕（ハイエンドな代替案）
- 幸福度ランキングで初の1位となり、都心で働きつつ生活実感の充実を求める層の満足度が際立った。citeturn0search0
- 愛宕山（標高25.7m）は23区内で最も高い自然の山で、愛宕神社の杜がまとまった緑を提供し、都心でありながら静謐さを得やすい。citeturn0search8
- 山裾には愛宕グリーンヒルズなどの複合施設が並び、虎ノ門・神谷町エリアへ徒歩圏でアクセスできるため、国際都市機能と居住機能を同時に享受できる。citeturn0search8
- 留意点：幸福度調査は丁目単位でサンプルが限られるため、平均所得の高い単身・DINKS層にバイアスした結果の可能性がある（住みここち調査のような大規模サンプルではない点に注意）。citeturn0search4

## 4. 総合判断
住みここち（生活満足）と幸福度（主観的充足）の双方で高評価を得ているのは世田谷区松原と港区愛宕だが、サンプル規模と5年連続首位という安定性から、日常生活全般のQOLを重視する多様な世帯にとっては世田谷区松原が最も再現性の高い選択肢と考えられる。citeturn0search5turn0search0

## 5. 次に取るべきアクション
1. 2025年版ランキング（例年6月頃発表）をウォッチし、直近のトレンド変化がないか確認する。
2. 松原・愛宕の平日日中と夜間の騒音・人流を現地で計測し、体感とデータのギャップを埋める。
3. 自身のライフスタイルに合わせて、世帯構成や通勤先に応じた移動時間と住居コストのシミュレーションを行う。
